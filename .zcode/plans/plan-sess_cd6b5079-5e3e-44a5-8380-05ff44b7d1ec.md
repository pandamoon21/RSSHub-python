建议实施最小、面向根因的修复：
1. 修改 `rsshub/spiders/bjnews/channel.py` 的抓取策略，将移动 API 的多次尝试改为受总预算约束的并发/竞速请求，而不是串行等待。每个尝试使用独立守护线程和现有 `fetch_with_deadline`，第一个成功且能解析出有效条目的结果立即返回，其他请求不再阻塞响应。这样在 Vercel 10 秒限制内，把当前约 1/3~1/2 的单次成功概率提升为多次独立连接的合并成功概率，同时把失败路径压缩到一个固定时间窗口。
2. 保留桌面站作为快速首选和现有 `last-good` 逻辑；只调整移动 API 重试调度、线程收敛与日志，避免破坏频道映射和解析行为。若所有实时源失败，继续优先返回最近成功数据；没有历史数据时保留明确异常，避免把错误内容写入 SWR 缓存。
3. 增加针对抓取调度的可测试辅助函数或最小测试覆盖：验证一个并发尝试成功时能返回有效条目、全部失败时仍会走 `last-good`/异常路径，并确保不会超过请求预算。
